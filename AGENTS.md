# Agents

This project follows the open **Agent Skills** standard (`SKILL.md`).
Start with the selected project entry points below, not assumptions about the stack.

## Skills

Skills installed by the scaffold use a shared canonical copy under **`.agents/skills/`**.
Harness-specific paths (such as **`.claude/skills/`**) symlink to that canonical copy so
updates stay single-source and consistent across agents.

Skill folders (`.agents/skills/`, `.claude/skills/`, `.github/skills/`) are excluded from Biome:
their content comes from the skill's source and is replaced on every update, so local
reformatting would only be overwritten.

To check what's installed:

```bash
ls .agents/skills
ls -l .claude/skills
```

## Dev servers (pinned ports)

Each app runs on a **fixed, pinned port** — no proxy, no extra setup. `bun run dev`
from the repo root starts every app via Turbo; or run one on its own:

```bash
bun run dev                   # all apps (Turbo fans out)
cd apps/<app> && bun run dev  # one installed app, on its pinned port
```

The installed apps and their assigned ports are listed in the project **README**
("Dev servers" table). Each app's `package.json` pins its port in its `dev` script.
When adding an app, choose an unused port and update that table.

## Next.js generated types

`next-env.d.ts` is generated by Next and gitignored — never commit it. Every Next app's
`check-types` runs `next typegen && tsc --noEmit`, so route types exist before `tsc` runs
(including on a fresh clone or CI). Run `bun run check-types`, not a bare `tsc`.

## Project entry points

Use `.agents/skills/use-design-system/SKILL.md` when building an interface.
Scaffold-selected skills: `first-run`, `skill-base-ui-handbook`, `skill-contribute-component`, `skill-contribute-docs`, `skill-figma-fidelity-check`, `skill-figma-generate`, `skill-figma-library`, `skill-storybook-author`, `skill-tokens-studio`, `update-guidelines`, `use-design-system`. Run `ls .agents/skills` for later additions.
Configured MCP servers: `docs`, `figma`, `shadcn`, `storybook`, `tokens-studio`. Verify access before use.
- Read `packages/tokens` for the project's actual design tokens and installed CSS.
- Read `DESIGN.md` for portable design guidance and structured token values.
- Read `apps/docs/content/docs` for the owning conceptual and reference pages.
- Reuse components from `packages/ui` before creating a new component.
- Read `apps/docs/content/docs/about.mdx` for the maintained project tools and technologies list.
- Read the component stories in `packages/ui` for supported variants and interactions.
- Run `bun run storybook` from `packages/ui` to inspect component stories.
- Start agent-assisted work at `/docs/working-with-ai`.
- Use `/llms.txt` to discover documentation pages.

Validate with `bun run build`, `bun run check-types` and `bun run lint`; run affected package scripts too.
Run `bun run design:lint` after updating DESIGN.md.
Keep project-specific instructions outside generated marker pairs.
