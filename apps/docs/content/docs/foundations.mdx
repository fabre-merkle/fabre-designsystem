Foundations explain how the system expresses its character and helps people understand an
experience. Start with Principles, then explore the individual disciplines.

<Callout title="Authoring Foundations">
  Explain concepts and intent rather than listing token names, values, complete scales or
  component APIs. Visual examples may use the project's design decisions, but detailed
  references belong on their owning Tokens or component pages. Preserve each topic's start and
  end markers and its useful baseline when no project guidance replaces it.
</Callout>
