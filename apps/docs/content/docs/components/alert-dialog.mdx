## Installation

`AlertDialog` already ships in this project's component library, in the directory chosen when the project
was scaffolded. Import it from the project's namespace:

```tsx
import { AlertDialog } from "@workspace/ui/components/alert-dialog";
```

### Add or update from the design-system registry

This component is already installed in the design-system repository. To use it in another product, install from this design system's own published registry.

<RelatedPage href="/docs/registry">Configure the design-system namespace, published URL and any required credentials.</RelatedPage>

After publication, search for the component and use the exact item name returned by the registry:

```npm
npx shadcn@latest search @fabre-designsystem
npx shadcn@latest add @fabre-designsystem/<item>
```

Replace `<registry>` with this design system's namespace and `<item>` with the published name. If the registry is not published, use the installed source; do not substitute a different library. Review the diff before accepting an overwrite.

## Usage

```tsx
import { AlertDialog } from "@workspace/ui/components/alert-dialog";
import { Button } from "@workspace/ui/components/button";

<AlertDialog.Root>
  <AlertDialog.Trigger render={<Button variant="destructive">Delete</Button>} />
  <AlertDialog.Portal>
    <AlertDialog.Backdrop />
    <AlertDialog.Popup>
      <AlertDialog.Header>
        <AlertDialog.Title>Are you sure?</AlertDialog.Title>
        <AlertDialog.Description>This cannot be undone.</AlertDialog.Description>
      </AlertDialog.Header>
      <AlertDialog.Footer>
        <AlertDialog.Close render={<Button variant="secondary" mode="ghost">Cancel</Button>} />
        <AlertDialog.Close render={<Button variant="destructive">Delete</Button>} />
      </AlertDialog.Footer>
    </AlertDialog.Popup>
  </AlertDialog.Portal>
</AlertDialog.Root>
```

## API Reference

Alert Dialog adds no props to the Base UI parts. `Root`, `Trigger`, `Portal`, `Backdrop`, `Popup`, `Title`, `Description` and `Close` forward to the matching [Base UI AlertDialog](https://base-ui.com/react/components/alert-dialog#api-reference) primitives, preserving every prop, event, ARIA attribute, and the polymorphic `render` API.

`Header` and `Footer` are layout parts with no Base UI counterpart. Each renders a `div`, accepts any `div` prop and the `render` prop, and is optional.

| Part | Renders | Layout |
| --- | --- | --- |
| `AlertDialog.Header` | `div` | Stacks `Title` over `Description`. |
| `AlertDialog.Footer` | `div` | A row of actions aligned to the end. Below the small breakpoint the actions stack, in reverse order, so the last action in the markup sits on top. Put the primary action last. |

Nothing adds a corner close button, and the popup scrolls as before.

## When to use

Use `AlertDialog` for destructive or otherwise irreversible actions that demand explicit user confirmation. Unlike `Dialog`, an alert dialog cannot be dismissed by clicking the backdrop or pressing `Escape` — the user must engage with one of the actions. Use `Dialog` for non-blocking forms, settings, and focused tasks.

## Composition

Wrap any element with `render={<YourComponent />}` on `Trigger` and `Close` to use the project's `Button` (or any other element) as the interactive control. Base UI merges props and ref into the rendered element automatically.
