## How design and code connect

Code is the source of truth for components. Contracts describe how each component maps to a Figma component set, and Code Connect links library components back to their implementation.
Contracts belong to this Figma workflow: they describe design-library generation, not how application developers consume the React components.

## Before you start

Use a Figma file you have permission to edit and confirm the intended team, library and branch before generating. Make sure the project's fonts are available in Figma and its token variables and modes are ready.
Figma variables need exactly one writer. Follow the selected setup runbook to choose the writer; do not let a token-sync plugin and a generation tool independently create competing collections.

## What gets generated

| Resource | Role |
| --- | --- |
| Token variables and text styles | Shared visual values and typography, prepared through the selected token workflow. |
| Component sets | Contracted anatomy, variants, layout and variable bindings materialised from the compiled artifact. |
| Code Connect mappings | Links between Figma library components and their code usage; publishing requires the correct Figma permissions. |

Generation does not approve the library or guarantee visual fidelity. Review component geometry, typography, modes and bindings in Figma against the code examples.

## Keep design and code aligned

<Steps>
<Step>
### Prepare the source
Make and review the change in component source, tokens or the co-located contract. Update token exports using the project's selected token workflow; keep secrets out of documentation and committed files.
</Step>
<Step>
### Compile and check
From the project root:

```bash
bun run figma:contract
bun run figma:contract:check
```

Review the generated `.agents/figma-generation-contract.json` and commit the reviewed artifact with its source change. A successful compiler check is not visual acceptance.
</Step>
<Step>
### Generate and inspect
Follow the project's available Figma workflow to update the target library. Compiled contracts describe the intended result; they do not provide access to a generation tool.
Check the target file's variable collections, light/dark modes, fonts, variants and layout. Avoid hand-editing generated output as a substitute for fixing its source.
</Step>
<Step>
### Connect code and publish deliberately
Follow the Code Connect guide after the library components exist. Review generated mappings and confirm the target library and permissions before publishing; generation alone does not publish a library.
</Step>
</Steps>

## Troubleshooting

Missing variables usually mean the target file or variable writer is wrong. Missing fonts require the correct family and weight to be available in Figma. Regenerate stale artifacts using the project's contract scripts; do not bypass schema validation.

## MCP connection

Use this tool's MCP connection alongside the design system's Docs MCP and Registry MCP. Expand for setup; a configured server still needs authentication and a successful read-only test.

Keep installation project-local and preserve existing connections.
