## Connect to this design system

Use Docs MCP to understand the system, and Registry MCP to discover its published resources and prepare installation commands. Reading guidance and changing project files are separate actions.
For full coverage, use both servers: Docs MCP explains how and why to use the system; Registry MCP shows what is published and how to install it. Neither replaces the other.

| Connection | Use it for |
| --- | --- |
| Docs MCP | Find the owning guidance, token reference and component examples. It does not install registry items. |
| Registry MCP | Search the registries in `components.json`, inspect items and prepare installation commands. Your agent runs an approved command to install. |

<RelatedPage href="/docs/working-with-ai">Use project resources to find tool-specific setup and the shared AI workflow.</RelatedPage>

## Docs MCP

The documentation connection exposes this site's published pages through the native Fumadocs tools. It provides design intent and usage guidance, not a component installer.

### Docs MCP tools

The native Fumadocs server supports the following tools when deployed. Check your connected server's tool list; the table is not proof that an endpoint is available.

| Tool | What it provides | Example task |
| --- | --- | --- |
| `list_pages` | The page index, with owning page URLs. | Find the available token and component references. |
| `get_page` | One page's Markdown, requested by URL. | Read a component's usage and accessibility guidance. |
| `search` | Documentation results for a query, optionally scoped by locale. | Find the guideline that explains an interaction. |

## Registry MCP

Registry MCP uses the shadcn registry protocol. Its configuration key and executable are `shadcn`; its job here is to discover this design system's installable resources, not to replace Docs MCP.
It reads the registry namespaces in `components.json`. Configure the design system's published namespace first; starting the server alone does not select a registry or provide private-registry credentials.

### Registry MCP tools

| Tool | What it provides | Example task |
| --- | --- | --- |
| `get_project_registries` | The registries configured for the current project. | Confirm the design-system namespace before searching. |
| `list_items_in_registries` | Published item names from specified registries. | Browse the available resources without guessing names. |
| `search_items_in_registries` | Items matching a search query. | Find an existing component for the task. |
| `view_items_in_registries` | Item details, source files and dependencies. | Inspect what an installation would introduce. |
| `get_item_examples_from_registries` | Published usage examples, when the registry supplies them. | Inspect supported composition rather than inventing variants. |
| `get_add_command_for_items` | The CLI command for the chosen items. | Propose an installation for review; this tool does not run it. |
| `get_audit_checklist` | A checklist for reviewing generated changes. | Check the result after an approved installation. |

## Authenticate and limit access

A configuration entry is not an authenticated connection. Open your client's MCP settings, review the requested access and authenticate only the servers your task needs.
Keep tokens in your environment or the supported secret store, never in configuration files, documentation or prompts. Do not grant write or publishing permission merely because a server is available.

### Check the connection

Restart or reload your client's MCP connections after setup. Confirm that documentation search returns a page from this site and registry discovery returns the expected namespace before asking for changes.

If tools are missing, check the project file and server logs. If a private registry is unavailable, check its URL and required credential variables. An HTTP connection, authenticated session and permission to install are three different checks.
